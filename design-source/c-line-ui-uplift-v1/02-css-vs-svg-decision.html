② Hero / Flow · CSS-vs-SVG 体系决策

Codex 调研 (PR #173) 指出 v10 hero/flow 用 CSS 机器人头像，dispatch 14 角色用 SVG（基于 bot-avatar-v1）— 双 avatar 体系。本文档评估三个方案、给出推荐和落地路径。

OPTION A

保留 CSS 体系

Hero / Flow 继续 CSS，按 bot-avatar-v1 视觉重做 14 个 CSS variant

✓ Pros

  • 动画性能最好 — CSS transform / box-shadow / filter 合成层 GPU 加速
  • 装饰效果完整 — 呼吸光环 / podium / float / hover 缩放无需额外胶水
  • 现有 V10 代码改动小，只需扩 accent CSS vars
  • 已有 canonical-base.html 锁定的 CSS

✗ Cons

  • 双源 — dispatch (SVG) 和 hero (CSS) 同时维护，canonical 改一处不同步
  • 设计师改色 / 改眼形要分别更新 CSS 和 SVG
  • 14 角色 variant CSS scope 类 + face 内部 DOM 维护成本
OPTION B

统一到 SVG

CSS hero/flow 替换为 SVG，dispatch 和 hero 共用同一组 16 个 SVG

✓ Pros

  • 单源 — 16 个 SVG 文件即设计真相，dispatch 和 hero 同步
  • 设计师直接 export 替换 SVG，无需前端写 CSS
  • 14 角色 variant 完全声明式

✗ Cons

  • 装饰效果丢失 — 呼吸光环 / podium / glow / float 无法在 SVG 内表达
  • SMIL 动画兼容性差 / iOS Safari 可能卡顿
  • v10 hero CSS 大规模重构
  • SVG inline 内嵌后文件体积大，14 个 hero 实例同页面会重复
OPTION C · 推荐

混合：SVG 资产 + CSS 装饰

Body / face / symbol-eye 走 SVG（单源），呼吸环 / podium / float / hover 走 CSS wrapper（hero 专用）

✓ Pros

  • 视觉本体单源 — 16 个 SVG 是 dispatch 和 hero 共用真相
  • 装饰效果保留 — hero 用 CSS wrapper 包 SVG 加光环 / podium / float
  • 设计师改 SVG → 两边同步；改 hero 氛围 → CSS wrapper
  • 响应式动画走 CSS 性能更好

✗ Cons

  • 需要一次性建立 wrapper layer（前端工作量约 1 day）
  • 面屏内 symbol-eye 的眨眼动画需要 SMIL 或 wrapper class hook

对比维度

维度 A · CSS only B · SVG only C · Mixed（推荐）
资产单源 ✗ 双源 ✓ 单源 ✓ SVG 单源
装饰效果（光环 / podium / float） ✓ 完整 ✗ 丢失 ✓ CSS wrapper 保留
动画性能 ✓ GPU ▲ SMIL 兼容性 ✓ CSS GPU
设计师 → 落地路径 ✗ 两边改 ✓ 一次 SVG ✓ 一次 SVG
v10 改动范围 ✓ 小（扩 CSS vars） ✗ 大（重构 hero） ▲ 中（建 wrapper layer）
代码维护成本 ✗ canonical 改一处同步两边 ✓ 改 SVG 即可 ✓ 改 SVG / wrapper 分离
页面体积（hero 同屏 14 个） ✓ 1 套 CSS ✗ 14×SVG inline ✓ 14× 共享缓存
设计探索灵活度 ✓ DevTool 直接调 ▲ 需重新 export ✓ wrapper 在 CSS 调
★ 推荐方案

Option C · 混合架构

Body / face / ears / feet / symbol-eye 走 SVG（单源），呼吸光环 / podium / float / hover scale 走 CSS wrapper。 Dispatch (14 角色) 和 hero/flow 共享 avatars/*.svg；hero 额外包一层 .bot-frame wrapper 加装饰。

理由

  • 消除双源 — canonical 改 SVG，dispatch 和 hero 同步生效
  • 保留 V10 视觉氛围 — 呼吸光环 / podium 是 hero 灵魂，CSS wrapper 不丢
  • 性能最佳 — 装饰动画走 CSS GPU，SVG 静态资产 cache 命中
  • 设计师可直接交付 SVG，前端只需更新 wrapper class（与 14 角色 accent map 同步）

落地架构（伪代码）

// dispatch 端 (14 角色卡片) <img src="avatars/fundamental_analyst.svg" class="bot" /> // hero/flow 端（同一 SVG + CSS 装饰 wrapper） <div class="bot-frame bot-fund"> // CSS 装饰 <span class="ring"></span> <span class="ring d1"></span> <span class="ring d2"></span> <img src="avatars/fundamental_analyst.svg" /> // 单源 SVG <div class="podium"></div> </div> // CSS variant scope（accent / ring color / focus state） .bot-frame.bot-fund { --accent: #6ba3d4; --accent-rgb: 107,163,212; } .bot-frame.bot-news { --accent: #e89464; ... } .bot-frame.bot-onchain { --accent: #7dc488; ... } ... .bot-frame:hover img { transform: scale(1.05); } // hover 表情切换 .bot-frame.is-talking::after { ... } // 说话三点叠层

前端工作量预估

  • 建立 .bot-frame wrapper（≈ 半天，从 canonical-base.html CSS 抽离）
  • 14 角色 accent CSS map（≈ 1 小时，已在 README 列好）
  • hero/flow 端 DOM 替换为 wrapper + img（≈ 半天）
  • dispatch 端无改动（继续用 SVG）
  • 总计 ≈ 1 day
